## For reviewers — read this first
These findings are **already identified**. If your finding is listed here, **you don't need to
re-write it up** — unless you can add depth: a working exploit, a formal proof, a concrete fix, a
standard to map against, or a reasoned disagreement. **Net-new findings and deeper insight are
exactly what we're hoping you add.** What the proxies did *not* cover is at the bottom — that's
where fresh eyes help most. Named lenses are *grounded in the public work of* their namesakes,
never their opinions.

## Cross-lens convergence (conviction signal)
- **KF-01** flagged independently by **4 lenses** (security threat-model, systemic, forensics, agent) → highest conviction; likely the first mitigation. It is the root pattern behind KF-02, KF-06, and part of KF-07.
- **KF-11** affirmed by **5 lenses** → these are the load-bearing strengths; guard them as invariants, don't regress them while fixing the rest.
- KF-02 / KF-03 / KF-04 form an **enforcement/TCB cluster**; KF-05 is the **time** cluster; KF-08 / KF-09 the **ontology** cluster.

## Findings in detail

**KF-01 · Declarative, not authenticated.** Author-only status is gated by a self-written
document field `provenance.author_preseeded` (`TOOLS/lore_validate.py` Check 2); author identity
is unauthenticated git `user.email`; the agent-vs-author boundary and break-glass rely on
self-restraint. *Why it matters:* a provenance system that records claims of authority without
binding them to something unforgeable can be escalated by any writer or adversarial INTAKE.

**KF-02 · No enforcement at rest.** All checks run only when `lore_validate.py` is invoked; the
pre-commit hook is not installed (and rejects the mode-644 `INTAKE/raw/README.md` the validator
exempts, so it can't be installed as-is). Governance is opt-in. *Fix seed:* make enforcement
secure-by-default (CI + a working hook).

**KF-03 · Single-point / parser-differential enforcement.** `SimpleYAMLParser` is not a
conforming YAML parser; a crafted document can validate benign while reading differently to a
real tool or human. One validator, no defense-in-depth. *Fix seed:* conforming parser + a second
independent check.

**KF-04 · TCB undefined.** LORE never names its minimal trusted core / irreducible invariants —
exactly what the design source ("define the TCB for LORE") asked for. Everything else is harder
to secure until this exists.

**KF-05 · Governance-across-time unbuilt.** No succession model for "sole authority," no
consolidation/decay (unbounded accretion vs. legibility), and authority is not itself auditable
(no reciprocal transparency). Richly theorized in the design source, absent from the scaffold.

**KF-06 · Integrity advisory, not forensic.** `chmod a-w` is reversible and not git-preserved;
Check 5 (hash) fires only if `sha256`+`path` present; no append-only tamper-evident log;
break-glass is a document type, not an enforced/logged control.

**KF-07 · Agent consumption not realizable yet.** The `integration-contract` schema is a FUTURE
stub; there's no validated context-package an agent can consume, no machine-enforced
generated-vs-knowledge signal, and tool/capability delegation (agents' core need) is out of scope.

**KF-08 · Ontology thin/conflated.** `object-ref` is a single indirection whose target is never
resolved (Check 7 only checks the id is a string); the one `status` field conflates lifecycle,
authority, and epistemic state; key terms lack formal definitions.

**KF-09 · Prior art unmapped.** No positioning against W3C PROV-O, RDF, event-sourcing, or
archival standards (OAIS/ISO 14721). Risks reinvention and interoperability gaps.

**KF-10 · Complexity risk.** Growing surface (15-value status enum, transition matrix, multiple
schema types, indirection) — the Cold Review's "abstraction expansion" risk, from the minimalist lens.

**KF-11 · AFFIRM — protect these.** Separation of commonly-conflated concepts
(identity/authority/capability, OBJECT vs OBJECT_REF, evidence vs knowledge, generated vs
canonical); supersede-not-delete; preserved rationale & uncertainty; a dependency-free,
small-attack-surface validator. Five lenses independently called these out as strengths.
