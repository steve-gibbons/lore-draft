# GL-003 - "counter-" is a family attribute, not a separate "anti-" type

- **id:** GL-003
- **type:** guideline (strong) - terminology / ontology convention
- **status:** accepted  (author-proposed 2026-08-15)
- **date:** 2026-08-15

> EXPERIMENTAL / provisional. A naming + ontology convention: opposition lives *inside* a noun
> family as an attribute, not as a separate "anti-X" object.

## Convention
Contradicting or opposing instances use the prefix **`counter-`** and belong to the **same noun
family** as an attribute - not a separate "anti-X" type:
- **counter-evidence** - evidence *against* (an attribute of `evidence`; polarity = counter).
- **counter-claim** - a claim *against* (an attribute of `claim`).
- **counter-assertion** - likewise for `assertion`.

The base noun carries a **polarity / stance attribute** (supporting ↔ counter). A counter-X is a
*view of the same family*, so it inherits that family's lifecycle, provenance, and scope discipline.

## Rationale
"anti-this / anti-that" implies a separate opposing *type*. `counter-` keeps the opposition **inside
the family as an attribute** - ontologically truer, and it keeps disagreement first-class and
governed (cf. C27, "don't erase disagreement; keep conflicting assertions visible").

## Exception
**`anti-pattern` stays.** It is the established, correct term - an anti-pattern is genuinely a
distinct thing (a recurring *bad* pattern), not a "counter-pattern attribute of a pattern."

## Heed it internally
Prefer `counter-evidence` / `counter-claim` over ad-hoc "anti-X" in schemas, records, and prose;
model the polarity as an **attribute of the base object**, not a new object type.
